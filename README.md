## Overview

This repository contains an independent IAM QA automation framework for testing the fictional [IdentityFlow application](https://github.com/sachintechpro/identityflow). Automated checks validate authentication, session behavior, role-based authorization, recovery workflows, and selected Selenium browser journeys.

The application under test is a simplified educational IAM simulator. These tests do **not** claim Okta/OIDC integration, production identity security certification, or penetration-testing coverage.

## Public test reporting

1. Open the [Live Test Results Dashboard](https://sachintechpro.github.io/iam-qa-automation/) to see the latest execution status, overall counts, API and Selenium breakdown, and individual test outcomes.
2. Select **GitHub Actions run** for the exact underlying pipeline execution and commit.
3. For the full pytest HTML report or JUnit XML, open that run and download the `iam-qa-test-results` artifact. GitHub artifacts may expire under the retention policy.
4. Open the [Live IAM application](https://identityflow.onrender.com) for hands-on exploration of the functionality tested.

The public dashboard does not publish test stack traces, login secrets, session cookies, or failure screenshots. GitHub Actions remains the test runner; GitHub Pages hosts only a generated static results view.

## Test framework architecture

```text
GitHub Actions
├── Checkout IAM QA Automation
├── Checkout separate IdentityFlow source
├── Run pytest against isolated local app processes
│   ├── API tests (Python requests)
│   └── Selenium browser tests (Page Object Model)
├── Upload pytest HTML, JUnit XML, and test artifacts
└── Generate public dashboard from JUnit XML
    └── Publish to GitHub Pages
```

| Capability | Implementation |
| --- | --- |
| Selenium browser testing | [`tests/ui/test_login.py`](iam-qa-automation/tests/ui/test_login.py) |
| Page Object Model | [`framework/pages/identity_page.py`](iam-qa-automation/framework/pages/identity_page.py) |
| API test client | [`framework/api_client.py`](iam-qa-automation/framework/api_client.py) |
| Data-driven permissions | [`testdata/rbac_cases.json`](iam-qa-automation/testdata/rbac_cases.json) |
| Isolated tests and fixtures | [`conftest.py`](iam-qa-automation/conftest.py) |
| CI pipeline and Pages deployment | [`.github/workflows/qa-tests.yml`](.github/workflows/qa-tests.yml) |
| Public results generator | [`tools/build_dashboard.py`](tools/build_dashboard.py) |

## Report publication

The `qa-tests.yml` workflow runs on changes to `main` and manual dispatch. It builds the public dashboard from the run's own `results.xml`. When tests fail, failed tests are shown as **FAILED**, not overwritten with the last successful outcome. If test setup fails before JUnit output exists, the dashboard is labeled **INCOMPLETE**.

Pull requests execute tests but do not publish Pages, preventing unreviewed PR code from updating the public site.

### One-time GitHub Pages setup

1. Open the repository's **Settings → Pages**.
2. Under **Build and deployment**, set **Source** to **GitHub Actions**.
3. Open **Actions → IAM QA Automation Tests → Run workflow** on `main`.
4. When the **Publish test dashboard** job succeeds, visit **https://sachintechpro.github.io/iam-qa-automation/**.

No Render service or runtime secrets are needed for the dashboard. GitHub Pages does not execute the tests; the GitHub Actions runner does.

## Scope and limitations

- IdentityFlow uses fictional accounts and is not a real identity provider.
- Automated tests run against isolated local app instances, not the shared public demonstration.
- The Selenium suite covers a small sample of browser journeys; it is not comprehensive cross-browser testing.
- Test counts are derived from JUnit XML generated by the actual workflow. Their values may change with new test cases or failures.
- Public reporting is intentionally limited to case names, pass/fail/skip results, durations, and run metadata.
